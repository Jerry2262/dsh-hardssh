# 设计决策与已知限制

本文记录两类信息：已经确定的设计取向（为什么这样做），以及当前仍然存在的限制（待处理 / 待决策）。后者沿用问题队列的做法：记录是为了不遗忘，不是接受它。

状态：`已确定` / `待处理`（已确认，排队解决）/ `待决策`（需要先定方向）/ `等待外部条件`。

## 1. 已确定的取向

- **不注册第二套工具**。远端执行复用标准 `read` / `write` / `edit` / `bash` / `glob` / `grep`，由 seam 按会话 cwd 路由。这保证模型看到的工具面与本地会话一致，也避免两套语义漂移。
- **一个会话绑定一个工作区**。主机身份来自会话，不是面板里的全局选择；换服务器就是换会话。
- **连接配置不进入会话上下文**。插件不向模型注册任何 SSH / 主机 / 别名元数据；远端命令环境会剥离客户端 `DSH_*` 变量。
- **凭据默认明文存于本地配置文件**。`secretStorage: plain` 是默认值：密码/口令写在 `~/.dsh/dsh-hardssh-ssh.json`（0600、目录 0700），重启后不重新询问；`none`（不落盘）与 `vault`（AES-256-GCM 加密）保留为可选项。自用阶段优先可用性，磁盘上的明文凭据风险由文件权限兜底；后续可替换为加密或系统钥匙串，接口不变。
- **不隐藏远端事实**。模型可以读到主机与远端环境，与其让它反复推断矛盾，不如在系统提示里给一句明确说明；重点是让模型看到一致的路径（运行上下文 cwd、文件路径、`bash pwd` 都指向远端）。
- **anchor 是本地占位目录**。DSH 的 fs / subprocess 调用只带 cwd、不带会话身份，因此远端工作区在本地必须有一个稳定路径作为会话 cwd；远端根的真实路径由 router 解析。anchor 目录本身不承载数据。
- **远端沙箱 fail closed**。执行前优先验证 Landlock；仅可用性探测失败时验证已安装 bubblewrap 的绝对路径、版本、namespace 与读写拒绝能力。无可用后端即拒绝；上传失败或隔离拒绝测试失败直接停止。用户命令启动/执行失败不切换后端重跑。Landlock 内核/LSM/启动参数/编译状态诊断与 bwrap 错误共同说明拒绝原因。
- **操作日志只记管理操作**。插件的连接测试、目录浏览、工作区创建、沙箱部署进入日志；会话里的命令与文件操作留在会话轨迹。两类信息归属不同，混在一起会同时污染调试与隐私边界。
- **命令策略是护栏，不是沙箱**。`commandPolicy` 只按命令名/正则拦截，绕过方式很多；硬限制应放在服务器侧。
- **侧栏徽章只按原生工作区 id 绑定**。侧栏没有行装饰插槽，徽章仍是 DOM 注入，但行身份只认 `data-row-key="workspace:<id>"` 与绑定表；不得从标题文本等自己会写入的内容推导身份，也不得在每次 DOM 变动时重新计算。徽章内容（别名与远端根）在工作区生命周期内固定，只有连通状态会变；观察器只把被重渲染冲掉的徽章补回，回调合并到一帧一次且扫描幂等。标题兜底匹配已删除——它会读到徽章自身写进标题的文本，在删除工作区的行重渲染时形成增删死循环。

## 2. 权限与沙箱

- **远端 Landlock 只能部分强制**：旧内核上 `read-only` / `workspace-write` 虽生效，但 stderr 打印 `landlock-run: partial enforcement (older Landlock ABI)`，实际约束力弱于完整 enforce。目前只在少数机器上观察过。影响：远端写入隔离强度低于声明。**待决策**。
- **远端 subprocess seam 可以绕过 `commandPolicy`**：任何插件都能在绑定会话里 spawn 远端进程；策略只按命令文本拦截。影响：登录节点限制不是硬边界。**待处理**。
- **`danger-full-access` 下远端 `write` / `edit` 仍被限制在远端工作区根**：本地 danger 不限制路径，远端 `RemoteFileSystem` 无条件拒绝根外路径。影响：同一权限模式在本地/远端语义不一致。**待处理**。
- **远端读取也受工作区根限制**：读 `/etc/os-release` 这类根外路径会被拒，而模型没有收到这一限制的提示，可能反复尝试。影响：多轮无效操作。**待处理**。
- **远端会话仍能读取控制端的 DSH 基础设施目录**：`localRoots`（`$DSH_HOME`、`~/.agents`）对远端绑定会话仍按本地路由，模型可以读取技能、profile、会话日志、`dsh-hardssh-ssh.json` 等控制端文件；vault 目录被显式拒绝。影响：与「控制端元数据不在执行环境」的前置说明并存，模型仍可能发现本地/远端分裂。**待决策**。
- **Windows 客户端原生工具在远端会话中仍本地执行**：`pwsh` / `powershell` / `cmd` / `*.exe` 被视为客户端工具，绑定远端工作区时仍在本机 spawn。影响：远端会话并非完全隔离于本地机器。**待决策**。
- **arm64 `landlock-run` 资产未在真机验证**：目前只有 x86_64 实测。**等待外部条件**。
- **远端 bubblewrap 尚待真实 SSH 验收**：已有后端选择/拒绝/argv/不重放单测与可显式启用的本地真实 bwrap 测试，zen5-88 尚未通过真实 SSH 执行验收。bwrap 的 `/tmp` 为每次命令独立挂载，跨命令不保留；网络沿用远端环境。**等待外部条件**。

## 3. 测试与验证

- **真实 SSH 不在默认套件或 CI 中**：live SSH 用例默认跳过（需 `DSH_LIVE_SSH=1`），默认套件 721 通过 + 3 skipped（含本地真实 bwrap 的两个 opt-in 用例）；真实远端行为靠手工会话验收。影响：远端回归可能逃过测试。**待处理**。

## 4. 宿主升级适配

- **依赖的公共契约仍在变**：路由 seam 基于 `fs-sandbox` / `subprocess` / `bash-sandbox` 行与 `ctx.fs` / `ctx.subprocess` 契约，客户端依赖 slot 契约。影响：DSH 升级可能破坏挂载或行为。**待处理**。
- **模型可见路径重写依赖宿主内部方法**：公开 `llm/stream` waterfall 的 options 已被 deepFreeze，当前通过包装 LLM runtime 内部的 `streamWithRegistration` 把 anchor 路径翻译成远端路径。该方法改名或签名变化时包装 fail open，运行上下文 cwd 与 `bash pwd` 的不一致会重新暴露。影响：升级后可能出现模型注意力问题回归。**待处理**。

## 5. 产品边界

- **同一个 DSH 进程内无法用纯路径区分本地与远端会话**：fs / subprocess 调用只带 cwd。影响：做不到让内核工作区路径本身等于远端绝对路径。**待决策**（是否投入宿主级 workspace/provider 感知路径改造）。
- **不做多主机运维面**：批量执行、集群、隧道、传输页、远端终端页签都不在范围内。需要这些能力时应另建工具，而不是把远端工作区做成运维控制台。
